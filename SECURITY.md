# Security Policy

## Supported Versions

Please report security vulnerabilities for the latest released version of Plugin Autopilot.

## Reporting a Vulnerability

If you have discovered a security vulnerability in this repository, please **do not** open a public GitHub Issue.

Instead, use one of the following private disclosure routes:

### Option 1: GitHub Private Vulnerability Reporting (Preferred)

If the repository maintainer has enabled GitHub Private Vulnerability Reporting, you can submit a security advisory directly through the **Security** tab of this repository. This keeps your report tied to the repository and visible only to the maintainer.

### Option 2: Contact the Maintainer Privately

If private vulnerability reporting is not available, contact the maintainer through a direct and private channel (e.g., a verified email address or a private message on the maintainer's preferred platform). Do not include sensitive exploit details in public channels.

## What to Include in Your Report

- A description of the vulnerability and its impact
- Steps to reproduce the issue
- Any relevant logs, screenshots, or proof-of-concept code
- Your preferred contact method for follow-up

## What NOT to Publish Publicly

- Credentials, API keys, or private repository contents
- Live exploit secrets or weaponizable details
- Sensitive user or repository data

## Scope

This policy covers the Plugin Autopilot codebase, its skills, scripts, and release artifacts. It does not cover third-party services (ChatGPT, Codex, GitHub, CI providers) that users may invoke separately.

## Response

The maintainer will acknowledge receipt of your report as soon as practically possible and work with you to coordinate disclosure. No guaranteed response time SLA is provided.
